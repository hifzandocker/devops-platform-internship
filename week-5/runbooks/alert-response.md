# Week 5 — Alert Response Runbook

## 1. Purpose

This runbook describes how to investigate and respond to application alerts generated by Prometheus and delivered through Alertmanager.

## 2. Monitoring Interfaces

- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000
- Alertmanager: http://localhost:9093

These interfaces require their respective Kubernetes port-forward commands to be running.

## 3. HighHTTPErrorRate

Condition: Application HTTP 5xx error rate exceeds 5% for 2 minutes.

Investigation:
1. Open the Prometheus Alerts page.
2. Check the HighHTTPErrorRate alert.
3. Inspect application traffic and HTTP response codes.
4. Check application pod status and logs.

Commands:
- kubectl get pods -n gitops-demo
- kubectl logs -n gitops-demo deployment/microservices-gitops-backend -c backend

## 4. HighRequestLatency

Condition: P95 request latency exceeds 500 milliseconds for 2 minutes.

Investigation:
1. Open the Grafana DevOps Internship dashboard.
2. Inspect the Request Latency P95 panel.
3. Check application pod resource usage and logs.

Commands:
- kubectl top pods -n gitops-demo
- kubectl get pods -n gitops-demo

## 5. NoReadyApplicationPods

Condition: No ready application pods are detected in gitops-demo for 1 minute.

Investigation:
- kubectl get deployments -n gitops-demo
- kubectl get pods -n gitops-demo
- kubectl get application microservices-gitops -n argocd

Resolution:
1. Identify why application pods are unavailable.
2. Check deployment events and container logs.
3. Restore the required replicas.
4. Verify application pods become ready.
5. Confirm Argo CD reports Synced and Healthy.

## 6. Alert Notification Verification

1. Open Alertmanager.
2. Confirm the alert appears.
3. Check the configured email inbox.
4. Verify the notification contains the alert name and severity.

## 7. Recovery Verification

Run:
- kubectl get deployments -n gitops-demo
- kubectl get pods -n gitops-demo
- kubectl get application microservices-gitops -n argocd

Expected state:
- Backend: 1 ready replica.
- Frontend: 3 ready replicas.
- Application pods: 2/2 Running.
- Argo CD: Synced and Healthy.
- Alert condition: Resolved.

## 8. Tested Scenario

The NoReadyApplicationPods alert was deliberately triggered by scaling the frontend and backend deployments to zero replicas.

Prometheus transitioned the alert from Pending to Firing, and Alertmanager successfully delivered an email notification.

The deployments were restored to their original replica counts. All application pods became ready, and Argo CD self-healing was re-enabled.
